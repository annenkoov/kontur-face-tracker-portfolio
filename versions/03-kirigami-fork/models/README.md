# Модели

`face_landmarker.task` загружается при первом запуске из официального хранилища Google MediaPipe, проверяется как архив и используется для локальных ориентиров лица и коэффициентов мимики.

Классификатор выражений: `enet_b0_8_best_vgaf` из HSEmotion/EmotiEffLib (лицензия кода Apache-2.0). Приложение атомарно загружает и проверяет ONNX-файл в `%USERPROFILE%\.hsemotion` до создания распознавателя. Классы: злость, презрение, отвращение, страх, радость, нейтральное выражение, грусть, удивление. Их вероятности — только оценки выражения, не метки стресса.

Локальный AU-диагностический слой использует Py-Feat `Detectorv2` и при первом пригодном кадре загружает чекпойнт в кэш Hugging Face. Он оценивает 20 Action Units (AU01, AU02, AU04, AU05, AU06, AU07, AU09, AU10, AU11, AU12, AU14, AU15, AU17, AU20, AU23, AU24, AU25, AU26, AU28, AU43). Значения 0–1 — выход обученной модели, а не интенсивность FACS 0–5, не ручная разметка и не показатель стресса. Эти оценки остаются диагностикой и не входят в индекс. Для AU-модели выбирается CUDA, если PyTorch видит совместимую NVIDIA GPU; иначе используется CPU. Для этого компьютера доступна RTX 4060 Laptop GPU.

Код Py-Feat — MIT, но используемый v2 checkpoint и некоторые upstream-компоненты предназначены для некоммерческого исследовательского использования и не имеют общего коммерческого разрешения. Сохраняй уведомления авторов; перед распространением приложения, платным использованием или публикацией весов отдельно проверь актуальные условия. Веса бесплатны для скачивания, но это не означает, что лицензия модели стала MIT.

**Замер этого компьютера:** Python 3.13.9, Intel Core i7-13620H, RTX 4060 Laptop GPU 8 GB, PyTorch 2.15.0+cu134. На `single_face.mp4` из фикстур Py-Feat после прогрева полный `FaceAnalyzer` обработал 15/15 кадров: медиана 66,16 мс (около 15,1 кадра/с), p95 72,34 мс. Сам AU-слой: медиана 37,88 мс, p95 42,34 мс (около 26,4 кадра/с). Это воспроизводимый тестовый ролик, а не обещание FPS на любой веб-камере или освещении. На CPU AU-слой измерен примерно в 0,74 с/кадр; для плавного realtime на этом ПК включай CUDA PyTorch. Захват и анализ разделены потоками, а ожидает анализа только самый свежий кадр, поэтому медленная модель может пропустить кадры, но не должна создавать растущую очередь старого видео.

### Источники

- [Py-Feat installation и Python 3.13](https://py-feat.org/pages/installation/) и [модели Detectorv2 / 20 AU](https://py-feat.org/pages/models/).
- [Лицензирование весов Py-Feat v2](https://py-feat.org/pages/licensing_v2/).
- [MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/python): blendshape-коэффициенты и landmarks.
- [OpenFace AU reference](https://github.com/TadasBaltrusaitis/OpenFace/wiki/Action-Units): полезный FACS-инструмент, но его лицензия подходит только для некоммерческого исследовательского применения.

Сырые кадры не сохраняются проектом. Для честного сравнения моделей используй только вручную размеченные локальные crop'ы и `tools/benchmark_models.py`. Он сравнивает четыре поддерживаемые модели и для новых примеров — сохранённый crop с контекстом и восстановленный tight crop. Результаты считаются также после усреднения вероятностей внутри одной capture-сессии и класса, чтобы повторные соседние кадры не притворялись независимыми наблюдениями. Текущий runtime HSEmotion использует CPU Execution Provider.

Локальные вручную размеченные образцы по умолчанию хранятся в `%LOCALAPPDATA%\Kontur\labeled_faces`. Они остаются на компьютере. Модели дополнительных вариантов скачиваются и проверяются атомарно в `%USERPROFILE%\.hsemotion` при первом запуске benchmark.

Пример запуска из корня проекта:

```powershell
$env:PYTHONPATH = "src"
work\.venv\Scripts\python.exe tools\benchmark_models.py --output outputs\benchmark-report.json
work\.venv\Scripts\python.exe tools\train_personal_adapter.py outputs\benchmark-report.json
```

Сырые кадры не сохраняются автоматически. Для первого запуска и загрузки недостающих весов требуется интернет.
